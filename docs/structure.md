# Структура проекта

Проект разделён на две части:

- **backend** — бизнес-логика, работа с Kodik, Shikimori, загрузками, хранилищем и mpv;
- **gui** — интерфейс на GTK4 + Libadwaita.

Они не импортируют друг друга напрямую. Всё взаимодействие идёт через общий пакет `internal/api`.

## Дерево каталогов

Файлы в дереве показаны как планируемые; сейчас созданы только каталоги.

## Назначение каталогов

### `cmd/terebi`

Точка входа. Здесь создаются конкретные реализации backend и GUI, после чего backend передаётся в GUI как `api.Backend`. Другие пакеты не должны знать одновременно о backend и GUI.

### `internal/api`

Общий контракт между слоями:

- модели данных (`Anime`, `Season`, `Episode`, `Profile`, `Download` и т.п.);
- интерфейсы команд и запросов;
- события (прогресс загрузки, состояние плеера, ошибки);
- общие типы ошибок.

Пакет не должен импортировать GTK, Kodik, Shikimori, yt-dlp или mpv.

### `internal/backend`

Бизнес-логика приложения. Не должен импортировать `gotk4` и `internal/gui`.

- `app.go` — фасад, реализующий `api.Backend`, и связывание внутренних сервисов.
- `sources/kodik` — получение переводов, сезонов и эпизодов, вызов `BatogiX/kodik` для резолвинга ссылок.
- `sources/shikimori` — информация об аниме, профиль, авторизация и синхронизация.
- `catalog` — объединение источников, поиск, «Популярное», работа с кэшем.
- `profiles` — локальный и Shikimori-профили, списки, оценки.
- `history` — история просмотра, позиции, время выхода.
- `downloads` — очередь загрузок, ограничение параллельности, yt-dlp, продолжение после прерывания.
- `playback` — управление mpv, состояние воспроизведения, скриншоты.
- `cache` — кэш метаданных, постеров и обложек списков.
- `storage` — сохранение JSON, атомарная запись, пути XDG.
- `config` — настройки, их схема и значения по умолчанию.

### `internal/gui`

Интерфейс GTK4 + Libadwaita. Не должен импортировать `internal/backend`, `sources`, `downloads`, `playback` и внешние клиенты напрямую.

- `app.go` — `Adw.Application`.
- `window.go` — главное окно, заголовок и навигация.
- `onboarding` — первый запуск: выбор профиля и ввод токена Kodik.
- `pages` — экраны разделов.
- `player` — оверлей, таймлайн и кнопки управления.
- `settings` — формы настроек.
- `widgets` — переиспользуемые элементы интерфейса.
- `remote` — обработка клавиш, фокуса и кнопки «Назад».
- `assets` — иконки, CSS, сообщения и переводы, встраиваемые через `go:embed`.

### `packaging`

Файлы для установки: `.desktop`, AppStream-метаданные, иконки приложения.

## Правила зависимостей

```text
cmd/terebi  ->  gui
cmd/terebi  ->  backend
gui         ->  api
backend     ->  api
api         ->  только стандартная библиотека
```

Запрещено:

- `gui` → `backend`;
- `backend` → `gui`;
- `backend` → `gotk4`;
- `gui` → `sources/kodik`, `sources/shikimori`, `downloads`, `playback`;
- прямое чтение JSON или файлов из GUI.

## Взаимодействие слоёв

- Запросы и команды — через интерфейсы `internal/api`.
- Асинхронные события — через подписку на `api.Event`.
- Backend работает в горутинах, GUI доставляет события в GTK main loop через `glib.IdleAdd`.
- Плеер — единственное исключение: backend владеет mpv, а GUI передаёт ему нативный handle окна (например, через `AttachVideoSurface(handle uintptr)`).

## Куда добавлять новое

- Новый источник аниме — `internal/backend/sources/<название>` и подключение в `catalog`.
- Новый экран — `internal/gui/pages/<название>`.
- Новый переиспользуемый элемент — `internal/gui/widgets`.
- Новая настройка — `internal/backend/config` и форма в `internal/gui/settings`.
- Новая фоновая задача — отдельный сервис в `internal/backend`.
